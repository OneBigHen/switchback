### Correction — a local responsive pass is not a remote one

The 122/0 above was true on the development host and **not reproducible in
CI**. `tests/e2e/short-landscape-geometry.spec.ts` asserted the open Gravel
Goblin panel's geometry without stubbing the advisor capability, so it read
whatever the machine declared. Gravel Goblin is server-declared and key-gated
(ADR 0021): a host holding `GEMINI_API_KEY` / `ADVISOR_OPENROUTER_API_KEY`
renders the invite and a key-free host — every CI runner — never does. The
development host has both keys in `.env.local`; the Deep QA runners have
neither, so the same suite returned 118/4 remotely on 2026-09-08 (runs
34193496907 and 34266459995), failing that one test on all four projects.

`tests/e2e/helpers/planner-fixtures.ts` already declares the capability absent
for exactly this reason; this spec bypassed it by calling `page.goto("/")`
directly. It now stubs the capability present, which is what its layout
contract actually needs, and passes on a host with and without keys.

**Remote Deep QA on the head is the authority for this gate.** A local
`npm run test:e2e` on a key-holding host cannot certify it.

The 6 skips in the responsive suite are deliberate `test.skip` guards, not
silent gaps: the WebAuthn publish journey is `chromium`-only (3 projects skip),
and one short-landscape Ride check runs only at the narrow landscape viewport
(3 projects skip).

## Product defects found and fixed

Both were found by repairing tests, not by the tests as written. Both are
reachable by an ordinary rider.

### P1 — the minimized planner stranded the rider

The action dock is absolutely positioned against the deck's bottom, and nothing
counted it against the fixed 146 px peek height.

On a wide window the dock rendered 138 px tall inside that 146 px box and
covered the entire 70 px mini header, with `overflow: hidden` clipping what was
left. The mini header owns **"Expand planner"** and the selected-route identity,
so minimizing a planned route on a desktop or tablet left no way back into the
planner at all.

On a phone the same deck also carries the Free Ride peek actions: header 68 px +
peek actions 54 px + dock 78 px is 200 px in a 146 px box, so the Plan/Start
control was clipped away — and at 568×320 short landscape it fell off the bottom
of the screen entirely.

Measured before the fix (desktop 1280×800): deck `634→780`, mini header
`635→705`, dock `641→779`. After: header `571→641`, dock `641→779`, adjacent.

Fixed in `planner-deck.css`: a minimized deck carrying a dock sizes to its own
content, and the dock stays in flow — there is no scroll region beneath it to
overlay. The already-tuned case is unchanged; header plus dock still measures
exactly the peek height.

### P2 — the wide-window scroll region ran under the dock

On a wide window `.planner-scroll` is sized to stop where the dock begins, but
the shared expression reserved 148 px against a dock that measures 156 px (two
58 px rows, 14/16 px padding, a 9 px gap, 1 px top border), so the scroller ran
8 px underneath it.

Corrected in `planner-action-dock.css`, scoped to `min-width: 761px` and
expressed in existing tokens. Deliberately **not** corrected in
`--sb-sheet-dock-expanded-height`: that token also feeds phone scroll padding
that is already tuned, and raising it regressed the mobile-core geometry
contract by clipping a decision card 3 px above the deck. A repo unit test
(`route-prepare-readability-css-contract`) independently forbids a hard-coded
clearance here, which caught a first attempt that used a literal `156px`.

### The correction the audit got wrong

The audit recorded prepare-layout as expecting a retired `Show route details`
where "current V2 renders `Details for <route>`". That is not what the product
does. They are two different controls at two disclosure layers:

- `Details for <route>` on each decision card swaps the rail for the route
  details workspace;
- `Show route details` **inside** that workspace expands `#route-preparation`
  (`aria-controls="route-preparation"`).

Commit `486e972` acted on the audit's reading, substituted the card action for
the inner disclosure and dropped the disclosure entirely, so
`#route-preparation` never opened. Both are restored. The rail unmounts once the
workspace is open, which is also why the card action cannot reopen preparation
later in the test.

### The single highest-value fix

`openPlannerEditor` — shared by 38 call sites — clicked "Edit route" to open the
editor and then unconditionally clicked "Ride options". But `PlanOptions` is
wired `open={editing} onToggle={() => onEditingChange(!editing)}`: **"Ride
options" *is* the editing state.** The second click closed the panel again and
unmounted the start/finish fields. The helper now drives that disclosure to
open rather than flipping it.

`expandPhonePlanner` had a related fault: it asserted the composer prompt was
visible, in a stage where V2 deliberately collapses the composer behind "Edit
route" (`.planner-composer-shell.is-collapsed { display: none }`). The part that
only raises the sheet is now separate, and promises only that.

Between them these two helpers account for 14 of the 22 failures.

## Known intermittent — not a gate blocker, not resolved

Across five full Mobile Core runs on this branch, one WebKit failure appeared
once and did not reproduce:

`ride.core.spec.ts › off-route recovery presents a bounded rejoin action` —
`locator.tap` timed out after 15 s on a visible, enabled "Nearest rejoin"
button. It is the same class the audit recorded on "Finish recording".

Evidence gathered, so this is not mistaken for a moving-target product defect:

- the button is geometrically **stable** — 40 consecutive animation frames over
  3.7 s produced exactly **one** distinct bounding box;
- it passes 3/3 in isolation and 3/4 full runs (the other full-run failure was
  the chromium clip, a real defect, now fixed);
- `pinVisualClock` was ruled out as the cause: with the pinned clock rAF is
  *faster and more regular* (18 ms mean / 37 ms max) than without it (64 ms mean
  / 549 ms max).

The mechanism is not pinned down. It is recorded here rather than papered over:
it was **not** addressed by weakening the assertion, swapping `.tap()` for
`.click()`, or adding a sleep. The gate's certified result is the 48/48 run.
