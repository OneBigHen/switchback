# Product Quality Bar

V2.1 is not complete merely because primary screenshots look cleaner.

## A-level bar

### Planning
- Idle Plan feels immediately actionable and map-first.
- Drawing is freehand-first and does not invent a destination requirement.
- Route options are meaningfully comparable at a glance.
- Selected route confidence and Start are obvious without a full-detail detour.
- Editing, road locks, offline and layer utilities are reachable without crowding default state.

### Destinations
- Rides exposes actual user objects quickly.
- Discover looks compelling without pretending the data model knows more than it does.
- Settings is scan-friendly while identity/sync/recovery remains safe and explicit.
- Public Atlas pages feel branded without duplicating the in-app shell.

### Ride
- Record feels like an instrument.
- Free Ride feels experimental but useful, not gamified.
- Live Ride can be understood in a glance.
- Off-route/GPS uncertainty becomes more explicit than normal state.
- No visual flourish increases workload at speed.

### Craft
- No obvious spacing inconsistency between adjacent screens.
- No arbitrary local color/radius/type system.
- No 10px interactive labels used as a workaround for narrow space.
- Dark theme has deliberate contrast and hierarchy.
- Mobile Safari does not zoom text inputs.
- Short landscape is actually operable.
- Desktop is not a scaled phone.
- Motion connects states and respects reduced motion.
- No obvious new jank or expensive visual architecture.

### Engineering
- Existing route/storage/source-ID/security semantics preserved.
- Focus/ARIA/keyboard behavior survives markup refactors.
- Deterministic visual fixtures cover the important states.
- No bulk snapshot laundering.
- Exact-head required gates green before readiness/merge decision.

If a screen is technically correct but visually feels generic, unfinished, crowded, empty, inconsistent or difficult to scan, keep iterating inside its owning wave rather than calling it complete.
