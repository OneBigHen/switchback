# Interaction specification

Status: target behavior for the refactor, not a description of shipped completeness. Decision IDs refer to [PRODUCT-NORTH-STAR](PRODUCT-NORTH-STAR.md).

## Shared transaction contract

Every user change has an identifiable target, a base ride revision, a typed operation, validation, a visible outcome, and recovery. A pointer move only updates gesture presentation. Releasing a valid gesture creates one change. Repeated activation of the same pending operation does not submit duplicate work.

Explicit small edits—moving a stop, changing duration, excluding a selected road—calculate immediately after the user commits the control. Do not add an Apply confirmation to every normal edit. AI proposals and materially ambiguous changes show a preview with Apply/Discard. Drawing uses Done as its explicit commit. All routes generated by a preview are labeled proposed and cannot replace the active guided ride until applied.

The previous usable route stays visible during calculation. Show "Updating ride," elapsed progress when useful, and Cancel. Failed/cancelled updates preserve the last committed intent and result, retaining a recoverable attempted edit where appropriate. A successful update highlights the changed span and announces its measured time/distance change. New input invalidates older requests before aborting them. Late responses cannot update selection, notices, history, or the map.

Undo restores the entire prior authored intent: points, order, mode, time, surfaces, avoid areas, kept roads, segment preferences, and sketch intent. One gesture or AI Apply is one entry. Redo restores the same intent until a new edit branches history. Reuse a valid result from the same intent/provider-data version or show recalculation. Undo never reverses received closure/access evidence, a published upload, or recorded physical movement.

## First run and map

Show the available routing region and a start chip with provenance: "Current location," "Last used start," or "Choose start." Ask for location when the user invokes it or starts a workflow that needs it. Denial leaves search and map selection usable; do not silently claim the regional default is the rider's location.

Single click/tap selects an object. Background dragging pans unless a named drawing/area mode owns the pointer. Clicking overlapping routes opens a small choice list; selecting one highlights the matching card. Long-press/context menu offers Start here, End here, Add stop, and the relevant road/area action. Keyboard users have the same actions through search and the object list.

Only one gesture owns the map at a time: pan, point drag, route shape, sketch, polygon edit, or road selection. Escape, pointer cancellation, lost capture, and leaving the activity terminate it cleanly. No release event may also activate a map click or background placement. Entering another tool cancels the incomplete gesture without committing it.

Fit the route into the visible map rectangle after the initial result and explicit "Show whole ride." A user pan suspends automatic fit until requested again. Location follow has clearly distinct follow, north-up, and free-pan states; a location update must not move a manually chosen planning start.

## Planner and route selection

Default composer: visible start, place/ride request input, timeboxed ride entry, Draw, and Free Ride. Place names resolve to selectable results; narrative requests resolve to the same structured intent. Show enough of the interpreted intent to correct it before an expensive or ambiguous route request.

Preferences use "Road character," "Surface," and "Time flexibility." Bike suitability provides constraints, not another competing list of route styles. Surface choices are pavement, mixed with maintained dirt where supported, and dirt preferred. Terrain tolerance is separately expressed and limited by actual data. No numeric "technicality" slider without an evidence-backed meaning. Highway/toll exclusion each has one control.

Initially select the deterministic Best ride. Compare against the fastest route satisfying the same hard constraints. Show duration, distance, added time, useful road/surface evidence, and uncertainty. Offer up to three meaningfully different choices; fewer is preferable to cosmetic duplicates. Rename by role and distinguishing geography, not provider profile plus ordinal. Never change a user selection when alternatives arrive.

Selection highlights geometry immediately. Hover/focus previews are temporary and never change selection. Preparation is reachable from the selected summary in one action. Saved/download/export actions belong in a concise route menu or preparation view, without exposing publishing forms until requested.

## Waypoints and route shaping

Stop and shaping point are distinct types. Stops are intended visits and appear in itinerary/arrival guidance. Shaping points influence geometry and stay out of spoken stop guidance. Both have stable IDs; reorder operations refer to IDs rather than current array indexes.

Add by map or search; insert at the selected segment or nearest valid position in travel order. Show the insertion before committing if multiple passes make it ambiguous. Dragging shows a ghost marker and candidate snapped location; release submits once. Keyboard editing supports coordinates/place replacement and Move earlier/later. Delete removes only the selected object and offers undo.

Dragging an existing route creates or moves a shaping constraint for that span. Show a tether/preview under the pointer; actual geometry comes from routing after release. Keep the start, destination, ordered stops, and unrelated kept/excluded sections. When the requested bend is unroutable, retain the old ride and explain the unsatisfied constraint at the location.

"Keep this road" selects a directed road span with adjustable endpoints. Default means keep this span while changing the rest; if it cannot be legally traversed, explain the conflict rather than quietly weakening it. An explicit secondary "Prefer if possible" changes this into a soft preference. "Avoid this road" creates an exclusion. Both appear in the constraint list and on the map, with edit/delete/undo. Do not expose fallback match tolerance as consumer terminology.

## Drawing

Entering Draw exposes Undo, Redo, Clear, Done, Cancel, and concise gesture guidance. First stroke in a new ride owns start and finish even when approximate location was auto-seeded. Deliberately authored anchors are shown with a visible "Keep existing endpoints" choice. A near-closed gesture proposes a loop with an editable join, rather than silently changing a destination ride.

Store the raw gesture and a derived corridor. Finger jitter may be simplified for routing; the original editable intention remains. Preserve traversal order through intersections and double-backs. Do not collapse a figure-eight into its perimeter or treat the nearest spatial point as the intended pass. Excess complexity produces a specific simplification/conflict preview, never fake connected road geometry.

A second stroke extends from a selected endpoint by default when near it; otherwise ask whether to replace or connect. Replacing a section is an explicit tool using two anchors. Undo removes the last stroke/edit unit, not one of hundreds of sampled points. Clear removes the current sketch with undo available. Cancel restores the pre-drawing ride and constraints.

Done requests legal road options, displays the faint sketch beside the result, and explains significant deviation. If adherence, duration, and eligibility conflict, offer a small set of real alternatives and identify the tradeoff. Failed routing retains the sketch for editing. Starting/ending near water or a closed road never silently moves the ride a large distance; show and approve a material snap.

## Avoid areas

Create a rectangle or polygon using a clear mode. Close/Done commits it once. An area has a stable ID, name, geometry, enabled state, and explicit exclusion semantics. Tap either fill or outline to select. Drag vertices or the whole shape; change geometry through one undoable transaction. Delete any selected area, not just the latest. Also provide a list with zoom-to/edit/delete for keyboard and crowded maps.

An endpoint inside an excluded area produces a located conflict with Move endpoint, Edit area, or Remove area. Do not bypass the area or draw a connector through it. Exclusions persist across AI edits, reroutes, Free Ride suggestions, refresh, and return-home unless the rider explicitly changes them.

## Free Ride and active guidance

Start Free Ride without a destination. Require a reliable current location for ahead-only guidance; allow map exploration without pretending to know heading. Optional stationary setup: road character, surface tolerance, return-by time, saved Home or session start as return point. Start recording according to an explicit visible choice; recording and guidance remain separate session attributes.

While moving, one quiet ahead suggestion may appear after workload and GPS checks. Show the road, additional minutes, known surface, and uncertainty. Accept navigates the suggested segment within the existing session. Completion returns to Free Ride; it does not end and restart the recording. Ignore and Less like this affect this session and optional local preferences without changing hard constraints.

"More dirt," "more pavement," "easier," and "more technical" modify future suggestions only. Easier/technical responses are bounded by known difficulty evidence; otherwise explain what can actually be changed. Extend changes the remaining ride budget. Turn around requests a legal route toward the prior safe return direction, not reversal of one-way geometry. Head home requires a known Home; if absent, offer session start or a chosen destination. Fatigue switches the objective toward low-workload, reliable return while preserving legal/access constraints.

Complex editing and AI typing are available when stopped. No modal conversation appears during motion. Unknown workload defaults to quiet behavior, not "normal." GPS loss retains the last reliable position with age/uncertainty, suspends ahead-only prompts, and never displays stale speed as fresh.

Off-route detection uses sustained deviation and route continuity. Reroute starts at reliable current position and includes only remaining intended stops, all active exclusions, and feasible kept sections. A failure preserves the original route/track and provides retry, return, or offline capability-specific recovery. Imported track-only navigation never invents turn instructions or silently road-routes the track.

Refresh restores the activity, remaining objective, exclusions, recording identity, and paused checkpoint. Resume requires explicit user action and fresh GPS. Closing a browser may prevent recording; never backfill the missing interval. Wake-lock and speech failures are visible but do not destroy the session.

## AI as a map control

The assistant sees a bounded snapshot of ride intent, route revision, candidate evidence, selected map object/span, capability availability, and location freshness. Home resolution stays explicit and may remain client-side. Missing referents such as "that area" must trigger a map selection or clarification. The model must not infer Home from the current destination or infer all-road absence from an empty POI search.

| Request | Intended operation | Required guard |
|---|---|---|
| Fun 90-minute ride | Set timeboxed intent and propose loop | Resolve origin; legal candidates; measured duration |
| Somewhere scenic | Suggest grounded destinations/corridors | Scenic evidence/source, real coordinates |
| No highways | Set highway exclusion | Verify result satisfies it; preserve other constraints |
| Mostly pavement, easy dirt | Set surface preference and conservative terrain tolerance | Difficulty uncertainty explicit |
| Make it twistier | Re-evaluate intent with more backroad emphasis | Compare added time; engine chooses candidates |
| Tired; get me home | Resolve return target + low-workload objective | Home known; preserve constraints; no unsupported arrival claim |
| Another option | Request distinct candidate | Deduplicate; avoid cosmetic reorder |
| Why this section? | Explain selected span's recorded decision evidence | Correct directed span/pass and provenance |
| Avoid that area | Create/edit exclusion from selected geometry | Require selected area; preview conflict |
| Keep this road | Preserve selected directed span | Verified road/geometry; no coordinate invention |
| Extend by an hour | Increase remaining budget, recalculate future ride | Preserve elapsed recording and destination intent |
| Interesting stop | Ground POI and preview insertion | Search radius/coverage disclosed; no result is not proof of absence |

Allowed tool categories: resolve place, search stops, inspect selected span, read evidence/capabilities, propose typed intent operations, and evaluate a proposed intent through the normal planner. There is no arbitrary store write, arbitrary network fetch, route geometry generation, or model scoring tool.

A proposal contains base revision, operation summary, preserved constraints, calculated result/delta if available, unresolved questions, and Apply/Discard. This is the useful AI output; prose is secondary. Revision mismatch invalidates Apply and offers a refreshed proposal. Repeated Apply is idempotent. Apply is one history entry; undo restores all affected fields.

Core requests continue without AI using controls/local intent interpretation. Errors distinguish invalid request, unavailable service, timeout, rate limit, and unsupported action. Keep the rider's text for retry. Do not label all of these "outside sources unavailable." Do not display internal route IDs or provider metadata in conversation.

## Discovery, GPX, saving, and preparation

Discovery unifies curated/public sources in one geographically useful list with source filters. Empty community content should offer curated/import/local alternatives. Details show original source, author where available, update time, route vs track, known surfaces, unknown difficulty, and privacy trimming. "Use this ride" creates a private derivative, preserving attribution and original geometry. It must not merely navigate to an empty planner.

GPX/KML/KMZ import validates type, size, geometry, segments, and archive bounds in a worker. Show progress/cancel; preserve the original. Disconnected segments require an explicit choice; never stitch across gaps. Multi-track files provide track selection/splitting. Route, track, and original exports explain their semantics; round-trip tests preserve waypoints/segments within declared limits.

Save is local and account-free. Autosaved draft recovery is distinct from the named library. Sharing previews exactly the sanitized geometry and names public/unlisted/portable semantics honestly. No publishing in an audit is required to prove a private save. Existing comments/notes require a migration decision before removal; private ride notes and source attribution remain valuable.

Preparation presents only relevant facts: route suitability/unknowns, weather/daylight where available, fuel exposure when supported, offline readiness for this exact corridor, and export. Multi-day staging appears for long trips or on explicit request. A thirty-minute ride does not need an expanded publishing, ratings, and multi-day dashboard.

## State coverage contract

Every task needs loading, empty, unavailable, failure, cancellation, offline, and recovery behavior. Loading does not erase the previous usable object. Empty distinguishes no results from service failure. Offline labels distinguish view saved route, display downloaded map, follow track, and compute a reroute. Recovery resumes the same ride revision or clearly identifies what could not be restored.
